## What BTI Voice Is

A shared VOIP/SMS desktop app for the BTI team to handle all calls and texts to/from veterinary practice customers. Built with React + Node.js/Express, deployed on Railway, using Twilio for calls/SMS, OpenAI for transcription/summaries, and Zoho CRM for auto-logging.

The app looks like a narrow mobile-style dialer (~420px wide), dark-themed. Five tabs: Dialpad (default), SMS, Calls, Contacts, Settings.

## Tech Stack (what each thing does)

- **React + Vite** → frontend UI, builds to `server/public/`
- **Node.js + Express** → server on Railway, all API routes, Twilio webhooks, Socket.io
- **PostgreSQL** → Railway-managed DB, 8 tables (see schema below)
- **Twilio** → SMS (inbound/outbound), browser WebRTC calls (Voice SDK), IVR, call recording, hold/resume/transfer
- **OpenAI Whisper** → transcribes call recordings (whisper-1 model)
- **GPT-4o-mini** → AI call summaries (Reason for Calling, Key Topics, Outcome, Sentiment)
- **Zoho CRM** → auto-logs all calls and SMS as CRM records/notes (fire-and-forget, never blocks user)
- **Electron v41** → wraps Railway web app in native Windows/Mac desktop app
- **Socket.io** → real-time push (new messages, call events, transcription ready)

## Key Technical Conventions

- **ALL colors** from `useColors()` hook — never hardcode. Dark: bg `#161b24`, panel `#1d2330`, surface `#252d3c`, accent `#4f9cf9`
- **No resolve mechanic in UI** — `is_resolved` exists in DB but frontend never writes it
- **Fire-and-forget Zoho sync** — always `setImmediate` + try/catch, never blocks user response
- **Single-pane navigation** — all tabs: list → detail → back, never split pane
- **Default tab** = `'dialpad'`
- **Notification bell** — localStorage key `bti_notif_seen_at`

## Known Gotchas

- **Git lock files:** OneDrive causes HEAD.lock and index.lock. Delete from `.git/` in File Explorer if git fails.
- **PowerShell blocks npm/railway:** Always use Command Prompt or Git Bash.
- **Railway "Redeploy" button** just restarts the old image — must run `railway up` for new code.
- **updates.js bug:** `download/:assetId` endpoint references `OWNER` and `REPO` variables that are never defined — runtime error if called. The version check endpoint (`/latest`) works fine. Download URL must be set directly as `LATEST_DOWNLOAD_URL`.
- **`is_resolved` route exists** (PATCH /conversations/:id/resolve) but there is no UI for it — intentional.
- **contacts.phone_number is UNIQUE** — only one contact per phone number currently.

## Feature Roadmap (full spec)

### Phase 1 — v1.1.0 (build simultaneously)

**1. Contact Create, Edit & Zoho Name Sync**
- New `GET /api/contacts` endpoint — returns ALL contacts (not just those with conversations)
- New `POST /api/contacts` — create a contact (name, phone_number, notes)
- New `PATCH /api/contacts/:id` — update name, phone_number, notes
- New `POST /api/contacts/:id/sync-zoho` — pull name from Zoho manually
- Auto-sync: in zohoSync.js, after a successful Zoho phone lookup, if the BTI contact's name equals the raw phone number (auto-assigned, never human-set), update name to Zoho Full_Name
- UI: `+` button in ContactsTab header, Edit button in ContactDetail, notes field visible/editable
- ContactsTab fetches from `/api/contacts` instead of deriving from conversations
- Decision: auto-sync only overwrites if name is still the raw phone number (human name is never overwritten)

**2. Unread Badges Per Conversation**
- New DB table: `conversation_reads (conversation_id, agent_id, last_read_at, PRIMARY KEY(conversation_id, agent_id))`
- New API: `POST /api/conversations/:id/read` — upserts last_read_at for current agent
- `GET /api/conversations` response includes `last_read_at` per agent
- UI: blue dot on ConvList rows where last inbound message sent_at > agent's last_read_at
- Dot clears when conversation is opened (fires read endpoint)
- Per-agent — reading marks it read for you only

**3. Missed Call Auto-Text**
- New columns on `ivr_settings`: `auto_text_enabled BOOLEAN DEFAULT false`, `auto_text_message TEXT DEFAULT 'Sorry we missed your call — we''ll get back to you shortly!'`
- In `webhooks/voice.js` — in the `/status` handler and `/no-answer` handler, when status is missed: check auto_text_enabled, if true fire Twilio SMS to the caller's number from TWILIO_PHONE_NUMBER
- UI: toggle + message textarea in SettingsTab under a new "MISSED CALLS" section
- New API: included in existing `GET/PUT /api/ivr/settings` (add new columns to response)

### Phase 2 — v1.2.0 (build simultaneously after Phase 1)

**4. Internal Notes on Conversations**
- New DB table: `conversation_notes (id, conversation_id, agent_id, body, created_at)`
- New API: `GET /api/conversations/:id/notes`, `POST /api/conversations/:id/notes`
- UI: notes section below messages in ChatPanel — distinct visual style (e.g. yellow/amber tint), shows author + timestamp, input field at bottom
- Notes are agent-only — never visible to customer, never sent via Twilio

**5. Canned Responses (Snippets)**
- New DB table: `snippets (id, title, body, created_at, created_by_agent_id)`
- New API: `GET /api/snippets`, `POST /api/snippets`, `PUT /api/snippets/:id`, `DELETE /api/snippets/:id`
- UI: button next to message input in ChatPanel opens a picker modal with list of snippets; clicking one inserts the text into the compose field (agent can still edit before sending)
- Manage snippets in SettingsTab under new "SNIPPETS" section
- Shared across all agents

**6. Quick Dial — Saved Contacts**
- New column on contacts: `is_pinned BOOLEAN DEFAULT false`
- New API: `PATCH /api/contacts/:id/pin` (toggles is_pinned)
- UI: star/pin button on contact detail page in ContactsTab
- DialpadTab Quick Dial section fetches pinned contacts from `/api/contacts?pinned=true` and renders them as tap-to-call buttons

### Phase 3 — v1.3.0 (sequential)

**7. Agent Status (Available / Away / DND)**
- New column on agents: `status VARCHAR(20) DEFAULT 'available'` (values: 'available', 'away', 'dnd')
- New API: `PATCH /api/agents/me/status`
- Socket.io: broadcast `agent_status_changed` event when any agent changes status
- UI: colored status dot in TitleBar next to agent name, click to cycle/set; Team section in Settings shows all agent statuses live
- Voice webhook: when routing calls (ringAllAgents, dialAgent), skip agents where status != 'available'

**8. Conversation Assignment**
- New column on conversations: `assigned_agent_id INTEGER REFERENCES agents(id)`
- New API: `PATCH /api/conversations/:id/assign` (body: { agent_id })
- Socket.io: emit `conversation_assigned` to notify the target agent
- UI: "Assign to" dropdown/button in ChatPanel header; assigned conversations show agent pill in ConvList; notification to assigned agent via existing bell/activity system
- Works best with Agent Status (assign to Available agents)
